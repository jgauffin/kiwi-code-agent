# Decisions for Parallell session support

### Stale-write and unread-file refusal exists today only for the own-loop engine
- on: Stale write refused, Own writes are seeing, Unread file refused, No read-before-edit instruction
- finding: `ReadTracker.staleness` in `src/agent/openai-session/tools/read-tracker.ts` already refuses an unread or changed-since-read file, but it is called inline from `write.ts`/`edit.ts`, which are wired only for `openai-compatible` sessions (`extension.ts`, the `allTools` built for that engine). Claude-engine (`claude-sdk`) sessions use the SDK's native Edit/Write instead of these tools, and `SdkSession`'s `ReadTracker` (`sdk-session.ts`) is only reachable by the "own tools" MCP server, never by the native file tools; the generic `preToolUse`/`postToolUse` hook point that both engines share (`session/hooks.ts`) currently has no hook enforcing staleness on either engine's native edits. `docs/intent/agent.md#Verification` itself lists "read-before-edit staleness enforced in a hook rather than by prompt" as parked, i.e. not yet built the way the spec now needs it. Where the check is built (kept inline and duplicated per own-loop tool, or moved to the shared hook so it also reaches the Claude engine's native Edit/Write) is open, and it decides whether "every session that writes... is held to the same check" can hold for the Claude engine at all.
- proposed: a write to a file whose content changed since this session last saw it is refused where the session's writes pass through KiwiAgent's own file tools, and on an engine that edits files itself the session is told of the change instead and the write stands.
- proposed: a write to a file whose content changed since this session last saw it is refused, and where the write cannot be stopped in time the session is told at once that it wrote over another hand's change and which file it was.
- recommended: keep
- because: the other hand can be at work against any session the person happens to have open, so a rule that holds on one engine and not the other leaves exactly the silent overwrite this feature exists to remove.
- ruling: keep
