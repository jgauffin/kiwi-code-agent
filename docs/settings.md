# Settings

*Kiwipow Agent: Settings* (or the gear in the Sessions and Chat views) opens a page in the editor with several tabs: Models and Advanced write to user settings, Permissions, Project and Remote to the workspace. Models has its own Providers and Profiles sub-tabs. API keys go to the editor's secret storage from the Providers sub-tab, under the provider's own name; a rename carries the stored key with it, so nothing else names it. A `claude-sdk` provider's key is optional: with one, Claude sessions use that Anthropic API key; without one, they use the Claude Code login on this machine.

The keys, for settings.json:

- `kiwiAgent.providers`: where models come from: `name`, `engine` (`claude-sdk`, `claude-installed` or `openai-compatible`), and `models`, the list to pick from; `openai-compatible` also takes `baseUrl`, and `reasoningControl`: `reasoning_effort` sends a profile's effort as that parameter (low, medium, high; higher levels are sent as high), `none` sends none, absent leaves it to a built-in table of models known to take it. The Providers sub-tab can fill `models` from the endpoint's own list once a base URL and a key, typed or already stored, are both in place. Example:

  ```json
  { "name": "berget", "engine": "openai-compatible", "baseUrl": "https://api.berget.ai/v1", "models": ["moonshotai/Kimi-K3"] }
  ```
- `kiwiAgent.profiles`: a named way to work: `name`, `default` (a `{provider, model}` naming an entry in `kiwiAgent.providers`, plus optional `effort` and `systemPromptFile`), and optional `steps`, one entry per step (`chat`, `code-plan` and `code-build` (Plan: planning and building the approved plan), `plan` (feature planning's spec), `reconcile`, `implement`, `fix`, `cleanup`, `docs`, `docs-map`, `file-decisions`, `doc-migration`) with a model or an effort of its own. The Profiles sub-tab shows them in a tab per kind of session. A step not named in `steps` still runs, on the default, so a step added later needs no profile changed. `fix` is the run that mends a failed test sweep. `code-build` must run on the same engine as `code-plan`: the approved plan exists only in its conversation, which carries over only within one engine.

  Effort: a step's own, else the one suggested for the step (plan, reconcile and code-plan high, implement, fix, code-build, docs, file-decisions and doc-migration medium, cleanup and docs-map low), else the default's. A fix goes one level higher for each sweep in a row that failed. Example, the strongest reasoner for planning and mapping, throughput for the rest:

  ```json
  { "name": "Balanced", "default": { "provider": "Claude", "model": "claude-sonnet-5-5[1m]" }, "steps": { "plan": { "provider": "Claude", "model": "claude-opus-5-5[1m]" }, "reconcile": { "provider": "Claude", "model": "claude-opus-5-5[1m]" } } }
  ```

  On `claude-sdk` and `claude-installed`, the `[1m]` suffix gives the model its 1M-token context window.

  Both Claude engines speak the same Agent SDK and give a session the same tools, instructions, skills and permissions; they differ in which Claude Code runs it. `claude-sdk` runs the one bundled with the extension, so the models it serves are fixed at the version the extension was built against. `claude-installed` runs the Claude Code on your own machine, which is how a model newer than the bundled engine knows is reached: you update that install rather than wait for this extension. That engine is offered only once a Claude Code is found, and a provider on it needs no key of its own, running on the same Claude login as the bundled one.
- `kiwiAgent.activeProfile`: the profile name new sessions run on.
- `kiwiAgent.permissions.grants`: answers kept from permission prompts for this workspace, each an allow or a deny of an action (read, write) or a command at a place, reaching a file, a directory or the tree below it. Answers kept for you rather than the workspace live in `~/.kiwi/permissions.json`, and the Claude engine's own `permissions` rules in `.claude/settings.json`, `.claude/settings.local.json` and `~/.claude/settings.json` count too. Reading in the workspace never asks. Where a session's own instructions are kept counts as its own ground: skills and the files they ship, sub agent definitions, memory notes and your `AGENTS.md` are read without a prompt wherever they live, while writing there asks like any other write. A write to the root `package.json`, `.vscode/settings.json`, `.mcp.json`, a root `.code-workspace`, `.claude/settings*.json` or where your own answers are kept is always asked, whatever is kept or the Allow writes switch says: those files decide what runs without asking. Permissions tab, where each answer reads as the sentence it was kept as. How calls are judged: [features/permission-engine.md](features/permission-engine.md).
- `kiwiAgent.permissions.denyGitWrites`: blocks every git command that is not read-only, whatever the allow rules say. Permissions tab, Git.
- `kiwiAgent.nodePath`: Node executable for the Claude engine; empty uses VS Code's executable.
- `kiwiAgent.claudeCodePath`: which Claude Code a `claude-installed` provider runs. Empty takes whichever is on PATH, else the one the native installer puts in your home folder. A path naming nothing leaves that engine unavailable rather than falling back to another install, so a typo shows as the engine going missing.
- `kiwiAgent.modelUpgradeDismissed`: set when you turn down the offer of newer Claude models, so it is not put to you again. The offer appears where the installed Claude Code can run a newer model than a profile does: once as a notification, and on the Models tab until taken or turned down. Taking it adds a provider on that install and moves the profiles that named a superseded model, leaving the models they ran configured.
- `kiwiAgent.compactAtTokens`: compact a conversation once it is this large, even when the window holds more, since every request re-sends it; 0 compacts only when the window runs short. Settings page, Advanced tab. A provider can set its own per model (`compactAtTokens` on the provider, model id → tokens), edited beside each model under Models › Providers; that wins for sessions on that provider and model.
- `kiwiAgent.traceEngine`: one line per Claude engine message in the Kiwipow Agent output channel, to see what the engine sends (thinking deltas, status) when the UI shows nothing.
- `kiwiAgent.verify`: test commands run once every task of a feature is marked tested, over the files the tasks name, in the directory of the nearest `project` file; a repo with a backend and a frontend runs each suite once, and only the suites the feature touched. A failure is handed to the implement session, up to `kiwiAgent.verifyFailureBudget` consecutive failures. Default: `dotnet test` of the `.csproj` owning a `.cs` file, `npm test` in the `package.json` folder owning a `.ts` file. A rule's optional `build` is how the implement session builds the project of a matching file; the test run never runs it. The implement session runs both without asking.
- `kiwiAgent.planIgnore`: globs under `docs/` feature planning must not see. The docs map does not describe them and *Clean up docs* does not touch them.
- `kiwiAgent.cutCoveredDocs`: on approval the planner cuts the doc sections the spec now covers or contradicts, each edit confirmed. Off (the default), it lists them in chat and edits only what you ask.
- `kiwiAgent.startBuildOnApproval`: on (the default), a clean check after approval starts the build by itself. Off, the feature is checked and mapped and then waits for *Implement*, so several features can be taken to build-ready while one is built at a time. The toggle beside *Approve* on the plan bar writes it.
- Command *Kiwipow Agent: Build Docs Map* describes the docs that changed since the last build. A planning session and *Clean up docs* do it themselves when the map is behind.
- `kiwiAgent.docsMap.style`: `described` (default) has a model write one line per section; `outline` gives headings with line ranges and each doc's opening paragraph, read at session start at no model cost. Set it to compare the two.
- `kiwiAgent.remoteControl.enabled`: lets this workspace pair with a phone over the forwarding service. Off by default. Settings page, Remote tab, where *Pair a phone* produces a code shown as text and as a QR code; presenting it once on the phone pairs it, and the tab lists every paired phone by the name it gave and when it last connected, each with its own *Unpair*.
- `kiwiAgent.remoteControl.serviceUrl`: where that forwarding service lives; the agent only ever connects out to it, never the other way.

## Instruction files and skills

Claude Code's layout, at the user level and in the workspace. On the own-loop engine `CLAUDE.md` and `AGENTS.md` under `~/.claude/`, `~/.codex/AGENTS.md`, `~/AGENTS.md`, then the workspace's `CLAUDE.md` and `AGENTS.md` join the system prompt, global first. Skills (`<folder>/SKILL.md`) under `~/.claude/skills`, `~/.kiwi/skills` and the same two folders in the workspace load through the `Skill` tool; the workspace wins on a shared name. The Claude engine reads the workspace's `CLAUDE.md` and skills itself. Details in [features/instructions-and-skills.md](features/instructions-and-skills.md).

## MCP servers

`.mcp.json` (Claude Code's format) gives chat sessions its servers' tools on both engines, as `mcp__<server>__<tool>`. They ask before running unless an allow rule names the tool or `mcp__<server>__*`. A save of the file reaches running sessions.

Servers start lazily: a session offers the tools a server listed when it last ran and starts the server only when one of them is called. A server never run in this workspace, or whose entry in the file changed, is started once to learn its tools. The composer shows each server by name with a light, green while it runs and red while it does not, and a click on it starts or stops it; a stopped server starts again on its next tool call.

`~/.mcp.json` holds the servers every workspace gets and the workspace's own `.mcp.json` goes over it, so a workspace can replace a user server by name. Only the workspace file is watched; a change to the user's takes effect on the next window.

Claude Code itself keeps the user's servers in `~/.claude.json` instead, under `mcpServers`. The first time it runs, Kiwipow Agent copies them into `~/.mcp.json` so both read the same list — verbatim, `${VAR}` placeholders and all, leaving out any name the format refuses. It copies only when there is no `~/.mcp.json` yet, so a server removed afterwards stays removed; to run the copy again, delete the file. Servers Claude Code holds per project (`projects` in `~/.claude.json`) are left where they are.

## Logs

Session events are logged to `.kiwi/runs/<session id>/events.jsonl` in the workspace, with the text the extension writes for a session (kickoffs, handoffs, hook context) compressed rather than readable; add `.kiwi/` to the workspace's `.gitignore`. Generated context lives beside the logs: the repo map under `.kiwi/repo-map/` and the docs map under `.kiwi/docs-map/`, both rebuilt from the workspace and safe to delete. A feature's review, decisions and tasks live under `.kiwi/specs/` until the feature is finished (see [plan-sessions.md](plan-sessions.md)).
